# Git Commands — Local, Remote, Merge Conflicts & Patch

Here is a **lab/exam-friendly Git command sheet** with the command and a short explanation beside it.

## 1. Git Configuration

| Command                                            | Explanation                 |
| -------------------------------------------------- | --------------------------- |
| `git --version`                                    | Check installed Git version |
| `git config --global user.name "Your Name"`        | Set your Git username       |
| `git config --global user.email "you@example.com"` | Set your Git email          |
| `git config --list`                                | View Git configuration      |
| `git config --global --list`                       | View global configuration   |

---

# 2. Local Repository Commands

### Create / Clone

| Command           | Explanation                               |
| ----------------- | ----------------------------------------- |
| `git init`        | Create a new local Git repository         |
| `git clone <URL>` | Copy a remote repository to your computer |
| `git status`      | Show current repository status            |

### Files

| Command                  | Explanation                            |
| ------------------------ | -------------------------------------- |
| `git add file.txt`       | Add one file to staging                |
| `git add .`              | Add all changed files to staging       |
| `git add -A`             | Stage all changes, including deletions |
| `git restore file.txt`   | Discard unstaged changes in a file     |
| `git rm file.txt`        | Delete a file and stage the deletion   |
| `git mv old.txt new.txt` | Rename/move a file and stage it        |

### Commit

| Command                    | Explanation                                     |
| -------------------------- | ----------------------------------------------- |
| `git commit -m "message"`  | Create a commit                                 |
| `git commit -am "message"` | Stage tracked modified/deleted files and commit |
| `git log`                  | Show commit history                             |
| `git log --oneline`        | Show compact commit history                     |
| `git show <commit-id>`     | Show details of a commit                        |

### Undo / Change Commits

| Command                    | Explanation                                     |
| -------------------------- | ----------------------------------------------- |
| `git commit --amend`       | Modify the most recent commit                   |
| `git reset HEAD~1`         | Undo last commit but keep changes               |
| `git reset --soft HEAD~1`  | Undo commit and keep changes staged             |
| `git reset --mixed HEAD~1` | Undo commit and unstage changes                 |
| `git reset --hard HEAD~1`  | Undo commit and discard changes                 |
| `git revert <commit-id>`   | Create a new commit that reverses an old commit |

⚠️ `git reset --hard` can permanently discard uncommitted work.

# 3. Branch Commands

| Command                         | Explanation                       |
| ------------------------------- | --------------------------------- |
| `git branch`                    | List local branches               |
| `git branch -a`                 | List local and remote branches    |
| `git branch <branch-name>`      | Create a branch                   |
| `git switch <branch-name>`      | Switch to a branch                |
| `git switch -c <branch-name>`   | Create and switch to a new branch |
| `git checkout <branch-name>`    | Older way to switch branches      |
| `git checkout -b <branch-name>` | Create and switch to branch       |
| `git branch -d <branch-name>`   | Delete merged branch              |
| `git branch -D <branch-name>`   | Force-delete branch               |
| `git branch -m <new-name>`      | Rename current branch             |

### Example

```bash
git branch feature-login
git switch feature-login
```

Or in one command:

```bash
git switch -c feature-login
```

# 4. Remote Repository Commands

A **remote** is the GitHub/GitLab repository connected to your local repository.

| Command                             | Explanation                  |
| ----------------------------------- | ---------------------------- |
| `git remote -v`                     | Show remote repository URLs  |
| `git remote`                        | Show remote names            |
| `git remote add origin <URL>`       | Connect local repo to remote |
| `git remote remove origin`          | Remove remote connection     |
| `git remote rename origin upstream` | Rename a remote              |
| `git remote set-url origin <URL>`   | Change remote URL            |

### Typical setup

```bash
git init
git remote add origin <GitHub-URL>
git remote -v
```

# 5. Push Commands

| Command                                  | Explanation                    |
| ---------------------------------------- | ------------------------------ |
| `git push`                               | Push current branch to remote  |
| `git push origin main`                   | Push `main` to `origin`        |
| `git push -u origin main`                | Push and set upstream tracking |
| `git push origin feature-login`          | Push a branch                  |
| `git push -u origin feature-login`       | Push branch and set tracking   |
| `git push --all origin`                  | Push all local branches        |
| `git push --tags`                        | Push all tags                  |
| `git push origin --delete feature-login` | Delete remote branch           |

### First push

```bash
git add .
git commit -m "Initial commit"
git push -u origin main
```

After upstream is configured:

```bash
git push
```

# 6. Fetch and Pull

| Command                 | Explanation                                             |
| ----------------------- | ------------------------------------------------------- |
| `git fetch`             | Download remote changes without merging                 |
| `git fetch origin`      | Fetch from `origin`                                     |
| `git fetch origin main` | Fetch remote `main`                                     |
| `git pull`              | Fetch + merge changes                                   |
| `git pull origin main`  | Pull remote `main`                                      |
| `git pull --rebase`     | Fetch and replay local commits on top of remote changes |

### Difference

```text
git fetch
    ↓
Downloads changes
    ↓
Does NOT change your working branch
```

```text
git pull
    ↓
fetch + merge/rebase
    ↓
Updates your current branch
```

# 7. Merge Commands

### Basic merge

Suppose you're on `main` and want to merge `feature-login`:

```bash
git switch main
git pull
git merge feature-login
```

| Command                           | Explanation                              |
| --------------------------------- | ---------------------------------------- |
| `git merge feature-login`         | Merge feature branch into current branch |
| `git merge --no-ff feature-login` | Always create a merge commit             |
| `git merge --abort`               | Cancel an ongoing merge                  |

---

# 8. Merge Conflict — Complete Working

### Scenario

You have:

```text
main
  |
  A---B
       \
        C---D   feature
```

Both `main` and `feature` modified the same line.

### Step 1 — Switch to main

```bash
git switch main
```

### Step 2 — Merge

```bash
git merge feature
```

Git may show:

```text
CONFLICT (content): Merge conflict in file.txt
Automatic merge failed
```

### Step 3 — Check conflict

```bash
git status
```

You'll see the conflicted file.

### Step 4 — Open the file

Git marks the conflict like:

```text
<<<<<<< HEAD
Code from main
=======
Code from feature
>>>>>>> feature
```

Choose the correct code and remove:

```text
<<<<<<< HEAD
=======
>>>>>>> feature
```

### Step 5 — Stage the resolved file

```bash
git add file.txt
```

### Step 6 — Complete merge

```bash
git commit -m "Resolve merge conflict"
```

### Step 7 — Push

```bash
git push origin main
```

### Conflict workflow to remember

```text
git merge
     ↓
CONFLICT
     ↓
git status
     ↓
Edit conflicting file
     ↓
git add .
     ↓
git commit
     ↓
git push
```

### If you don't want to continue

```bash
git merge --abort
```

This returns the repository to the state before the merge.

# 9. Rebase Commands

| Command                 | Explanation                                  |
| ----------------------- | -------------------------------------------- |
| `git rebase main`       | Replay current branch commits on top of main |
| `git rebase -i HEAD~3`  | Interactively modify last 3 commits          |
| `git rebase --continue` | Continue after resolving a conflict          |
| `git rebase --abort`    | Cancel rebase                                |
| `git rebase --skip`     | Skip the current commit                      |

### Basic example

```bash
git switch feature
git rebase main
```

If there is a conflict:

```bash
git status
```

Fix the file:

```bash
git add .
git rebase --continue
```

To cancel:

```bash
git rebase --abort
```

# 10. Stash Commands

`stash` temporarily stores changes without committing them.

| Command                       | Explanation                      |
| ----------------------------- | -------------------------------- |
| `git stash`                   | Temporarily save changes         |
| `git stash push -m "message"` | Save changes with a description  |
| `git stash list`              | List stashes                     |
| `git stash pop`               | Apply latest stash and remove it |
| `git stash apply`             | Apply latest stash but keep it   |
| `git stash apply stash@{1}`   | Apply a specific stash           |
| `git stash drop`              | Delete latest stash              |
| `git stash clear`             | Delete all stashes               |

### Common scenario

You're working on a feature but need to switch branches:

```bash
git stash
git switch main
```

Later:

```bash
git switch feature
git stash pop
```

# 11. Git Patch Commands

A **patch** contains changes that can be transferred/applied separately.

### Create patch from unstaged changes

```bash
git diff > changes.patch
```

| Command                            | Explanation                      |
| ---------------------------------- | -------------------------------- |
| `git diff`                         | Show unstaged changes            |
| `git diff > changes.patch`         | Save changes as a patch          |
| `git diff --cached > staged.patch` | Create patch from staged changes |

### Create patch from commits

```bash
git format-patch -1 HEAD
```

Creates a patch for the latest commit.

For the last 3 commits:

```bash
git format-patch -3
```

### Apply patch

```bash
git apply changes.patch
```

Applies a normal diff patch.

### Check patch before applying

```bash
git apply --check changes.patch
```

### Apply a formatted commit patch

```bash
git am 0001-my-commit.patch
```

### Abort patch application

```bash
git am --abort
```

# 15. GitHub Workflow

### New project → GitHub

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin <GitHub-URL>
git push -u origin main
```

### Existing GitHub project

```bash
git clone <GitHub-URL>
cd project
```

Then:

```bash
git add .
git commit -m "Update project"
git push
```

# 16. Feature Branch Workflow

```bash
git switch main
git pull

git switch -c feature-login

# Make changes

git add .
git commit -m "Add login feature"

git push -u origin feature-login
```

Then merge:

```bash
git switch main
git pull
git merge feature-login
git push
```

### 🔥 One-line memory trick

```text
LOCAL:
init → add → commit → log/status

BRANCH:
branch → switch → merge

REMOTE:
remote → fetch → pull → push

CONFLICT:
merge → status → fix → add → commit → push

PATCH:
diff → .patch → apply

TEMPORARY:
stash → switch → stash pop
```
